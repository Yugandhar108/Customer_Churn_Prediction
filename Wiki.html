User Guide

  1. Install a supported Python version and create a virtual environment. Follow setup commands in README.md.
  2. Place the authorized customer dataset at data/raw/customer_churn.csv.
  3. Open notebooks/phase_1_data_loading.ipynb in VS Code or JupyterLab and run its cells from top to bottom.
  4. Review the dataset shape, sample rows, dtypes, missing-value counts, and numeric conversion report.
  5. Do not proceed to later phases until required fields and data-quality issues have been reviewed.

The current 205-row CSV contains five screenshot rows and 200 generated synthetic rows. Synthetic labels are deliberately associated with generated tenure patterns to exercise model fitting. Metrics and recommendations from it are not business findings. Replace it with the full approved dataset before interpretation. Raw CSV files are ignored by Git to reduce accidental sharing of customer records.

Functional Guide

Business objective

Estimate customer churn from account/service attributes and use measured results to inform retention actions. A model score is a prioritization signal, not proof that a customer will leave.

Planned workflow

  1. Load and inspect the source data; normalize TotalCharges to numeric.
  2. Count male and DSL customers; extract female senior customers using mailed checks and customers meeting tenure < 10 OR TotalCharges < 500.
  3. Visualize churn/stay proportions and internet-service category counts. The notebook validates expected categories and displays a count for each internet-service type, including zero-count categories.
  4. Encode churn and train models using tenure, tenure with dropout, and then tenure plus monthly and total charges.
  5. Compare held-out evaluation results and document evidence-based retention recommendations.

Phase 2 reports male and DSL counts, extracts female senior citizens paying by mailed check, and extracts customers with tenure under 10 months or total charges under 500. The two extracted groups use separate DataFrame variables.

Expected outputs

Phases 1-3 output data-quality summaries, counts, filtered DataFrames, a churn-distribution pie chart, and an internet-service count bar chart. Phase 4 outputs test confusion matrices and training-accuracy plots after the data-size check passes. Phase 5 compares accuracy, churn precision/recall, and F1, then reports comparison notes; results from synthetic demo records validate execution only.

Technical Guide

Stack and entry point

Python, Pandas, NumPy, Matplotlib, Seaborn, scikit-learn, TensorFlow/Keras, and Jupyter. The Phase 1 entry point is notebooks/phase_1_data_loading.ipynb.

Input contract

CSV path: data/raw/customer_churn.csv. Phase 1 checks for the following columns:

gender, SeniorCitizen, InternetService, PaymentMethod,
tenure, MonthlyCharges, TotalCharges, Churn

TotalCharges is parsed with Pandas numeric conversion; blanks and invalid nonblank values are counted and reported. The source file is not overwritten.

The supplied data dictionary describes Churn as binary (1/0) and lists customerID as an identifier. Verify the CSV's actual target values before modeling, and exclude the identifier from predictive features.

Phase 4 maps numeric 0/1 or categorical No/Yes churn values to binary labels, excludes incomplete model rows with a reported count, reuses one stratified 80/20 split, and fits feature scalers on training data only. Fitting is gated unless both classes and both split partitions have enough rows. Run python scripts/generate_synthetic_demo_data.py to rebuild the deterministic synthetic extension.

Phase 5 derives test-set precision, recall, and F1 from each model's confusion matrix, compares accuracy deltas for dropout and added features, and treats the highest-recall model only as a candidate for further validation. No metrics are fabricated when models were not trained.

Planned model/evaluation decisions

The brief proposes 12- and 8-unit dense layers, sigmoid output, Adam, binary cross-entropy, and 150 epochs. Input dimensions must match the selected features. Use one reproducible, stratified train/test split across model comparisons. Alongside accuracy and confusion matrices, report churn-sensitive metrics such as precision, recall, F1, and ROC-AUC; choose a decision threshold based on the retention use case.

Dropout rates in the brief are 0.3 and 0.2. Compare training and validation behavior; dropout is a regularization technique, not a guarantee of higher test performance.

FAQs

Where is the CSV?

The current file is a 205-row synthetic demo that includes the five screenshot rows. Obtain the full approved CSV and replace data/raw/customer_churn.csv before interpreting model results for the business.

Can I run Phase 1 without the CSV?

If the CSV is absent, the workflow reports its expected path and skips data inspection. Add the approved CSV and rerun the cells to inspect actual records.

Why is TotalCharges numeric conversion needed?

CSV exports can represent blank charge values as whitespace or strings. Numeric parsing makes subsequent quality checks and model preparation reliable while surfacing invalid entries.

What does the brief mean by an input layer with 12 nodes?

In a dense network, the input shape is determined by the number of selected features. The stated 12-node and 8-node layers should be treated as hidden-layer widths unless the project owner clarifies otherwise.

Why not judge models using accuracy alone?

If churn and retention counts differ substantially, accuracy can hide poor churn detection. Recall, precision, F1, ROC-AUC, and the confusion matrix add useful context.
